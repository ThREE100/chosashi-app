# 毎日ドリル 作成ルール（量産・網羅のための正本）

この文書が、朝・夜の問題を作るときの正本。分類のID（型・難度・ひっかけ）は `taxonomy.json`、各問の分類は `registry.json`、網羅の状況は `coverage/coverage.md`（自動生成）。評価と背景は `EVALUATION_day1-7.md`。

## 0. 1問を作る流れ（共通）

1. `coverage/coverage.md` を見て、**未出題の型・未使用のひっかけ・不足している分野／形式**から選ぶ（優先度1の型を先に）。
2. `python3 daily-drill/new_problem.py …`（朝／夜の別と型・難度を指定）で雛形と仮登録を作る。
3. 雛形の TODO を埋める（TODO が残ると `check_registry.py` がNG）。
4. `registry.json` の `traps`・`articles`（朝は `hard`）を実際の中身に合わせて直す。
5. `python3 daily-drill/check_all.py` がNG 0件。申請書・事例型の朝・新しい型は、問題文と条文だけを渡した別のエージェントに解かせて答えを比べる（`evening/review/`、`morning/review/`）。
6. A4に収まるか確認（夜は問題2枚。印刷時のクリップを外したPDFのページ数が2）。
7. 作成ごとにコミット。個人の演習結果・過去問の出典・年度は問題・解説に入れない。

## 1. 共通ルール

- **条文は原文で確認**：引用は `note-articles/laws/` の原文に一字一句あること（機械照合）。条文で決まらない書き方は出題しない。通達・先例は原文を確認できたものだけ使い、確認できないものは「原文は未確認」として出題しない。
- **現行法令を正**とする。過去問の改題の要素（変えた日付・人名）は使わない。法改正で扱いが変わる論点は、解説に「（本試験当時は〜）」と注を添える。
- **答えは本文に漏らさない**。求める点の座標は与える表に載せない。
- **数値の設計**：四捨五入の境目（x.xx5）に近い値を避ける。観測値は逆算して丸める。
- **ひっかけは1問に1つ以上**（`taxonomy.json` の ID で登録）。解説で「どこがひっかけか」を書く。

## 2. 朝（択一1問＋条文の空欄補充）

### 2.1 配分（7日あたりの目安。`taxonomy.json` の `morning_quota_per_week`）

| 区分 | 目安 |
|---|---|
| 分野 | 不動産登記法5・民法1・調査士法1（本番20問は 民法3・不登16・調査士1。民法は出題履歴のある条文に限る） |
| 形式 | 条文3・事例2・規則準則1・数量1 |
| 難度 | L1が1・L2が4・L3が2 |

### 2.2 難度の定義

- **L1**：条文の直接の言い換えが中心。
- **L2**：数字・主体・範囲のすり替えを含む。紛らわしい肢（`hard`）が1〜2個。
- **L3**：事例の当てはめ、規則・準則、複数条文の組み合わせ。本番の「迷う肢」。**L3は形式を「条文」にしない**（チェックされる）。

### 2.3 肢の作り方

- 5肢（ア〜オ）、正しい／誤りの組合せ5択。正解の数は2〜3個。
- **紛らわしい肢（hard）を1〜2個**入れ、登録簿に記録する。確認用の定番の肢と、判断用の肢を混ぜる。
- **誤り肢は、ひっかけの型で作る**：M1 数字（一月↔二月）、M2 主体（誰が申請・誰の義務）、M3 例外・但書の見落とし、M4 事例の当てはめ、M5 期間の起算日・手続の順序、M6 範囲（全部／一部、直接／間接）、M7 規則・準則・先例、M8 似た制度・用語の取り違え、M10 義務と努力義務。
- **事例型**：「AはBから…を取得した。この場合、…」と、登場人物・日付を入れた短い事案にして、条文に当てはめる。事案の事実は肢の中で完結させる（前提を肢ごとに繰り返す）。
- **規則準則型**：規則・準則の条文（原文を確認できるもの）から出題する。期間・数値・記録事項など「覚える数字」が中心。
- **数量型**：期間・割合・桁数・個数だけを問う肢で構成する。
- 誤り肢は、**条文の言葉を1か所だけ変える**。まったく別の話にしない。誤りの理由は `note` に条・項・号つきで書く。

### 2.4 空欄補充（6分）

- 択一と**別の条文**にする（ヒントの重なり防止。`check_am.py` が検査）。
- 条文を号（項）の順に要約した表の、**判断のカギになる語**を空欄にする（記述式の穴埋めで問われる語）。1問7〜9空欄。
- 埋めた文が原文に一字一句あること（`…` は省略。各区間が原文の部分文字列）。

### 2.5 民法（第1作は `AM-008`＝共有物の使用・変更・管理。見本にする。追加するとき）

- 出題履歴のある条文に限る（`note-articles/` の過去問記事の出典から選ぶ）。
- 形式は事例型を中心にする（当事者・日付・登場人物を入れる）。分野は `registry.json` の `field` を `民法` にする。
- 原文は `note-articles/laws/` の民法の該当ファイルで照合する。

## 3. 夜（記述式）

### 3.1 配分と形式

- 7日あたり：**計算3・申請書4**（土地2・建物2）。月に1回は**統合演習**（本番の時間で土地または建物の1問）、月に2回以上は**L3**を入れる。
- 毎回A4で2枚（計算：1枚目＝回答欄を先頭に置いた問題文、2枚目＝図と表。申請書：1枚目＝問題文・登記記録・図・注、2枚目＝白紙の申請書）。
- 解答は別ページ（答え・図・つまずき、計算は電卓のキー列、申請書は記入例と根拠条文の引用）。

### 3.2 型と難度

型は `taxonomy.json` の `evening_types`（土地 T1〜T11、建物 B1〜B8）。

| 難度 | 内容 |
|---|---|
| L1 | 単独の型。点1〜2個、または欄の一部 |
| L2 | 2〜4点、または申請書1件。ひっかけ1〜2個 |
| L3 | 連鎖6〜8点、または複数登記・判断（公差・独立性など）つき。本番の1問に近い |

### 3.3 計算問題（calc2）

- **構成**：条件・聞き取り結果・注。参照する地積測量図・道路境界確認書・観測値は**表の題に作成年を書く**（例：「21番の地積測量図（昭和58年作成）に記載された座標値」）。回答欄は問題文の先頭。
- **聞き取り結果**には、事実・思い込み・誤情報を混ぜる（ブロック塀・擁壁・犬走りは筆界でない、など）。筆界は地積測量図・確認書の座標で判断させる。
- **図は座標から正確に描く**（`figure.py` の `svg_generic`）。求める点は赤い白抜き、座標値は図に重ねず別の表に出す。
- **連鎖（L3）**：後ろの点が前の点の計算結果に依存する設計にする。検算に使える情報（杭間の距離、隣地の地積測量図の辺長、地積の一致）を問題文に入れる。
- **作り方**：`templates/evening_calc_TEMPLATE.py` を `evening/build_PM-NN.py` にコピーして埋める。方法A（複素数）で答えを出し、`check_pm.py` に方法B（三角関数・クラメルの公式・射影・二分法・三角形分割）の検算を足す。
- **電卓**：キヤノン F-789SG の複素数モード。使うキーは `note-articles-Kijyutsu/prompt_note-kijutsu_tochi_kyoutsu.md` の「確認済みのキー操作」だけ。負の数は「0 − 数」で入れる。`calc_keys.py` にキー列を足し、`keysim_note_article.py` で実行して表示を再現、答えと一致をチェックに入れる。
- **丸め**：点は小数第3位で四捨五入して小数第2位、地積は求めた座標値（小数第2位）から座標法で出し、宅地は小数第2位未満を切り捨てる（規則第100条）。

### 3.4 申請書（shinsei2）

- 1枚目は本番の構成（事実関係・登記記録・測量成果や図・注）。事実関係は8〜10項目で、**ひっかけになる日付・人物・書類を混ぜる**（検査済証・引渡・契約・確認済証の日付、費用の負担者、施工者）。
- 日付は、**申請日（令和8年10月26日）から1か月以内**に収まるよう設計する（申請期限の問題を作らない限り）。
- 注で、答案用紙の書き方の約束（どの欄を空欄にするか、欄番号の冠記、添付情報の書き方）を書く。**印鑑証明書を「提供しないものとして答える」とは約束しない**：合筆・合体による登記等・建物の合併を所有権の登記名義人が申請するときは、添付情報に印鑑証明書を書かせる（令第18条第2項、規則第47条第3号イ（6）。本番の答案どおり。会社法人等番号を提供するときは規則第48条第1号で省略）。`check_pm.py` が機械で確かめる。**注で約束したことと解答がぶつからないこと**を独立照合で確認する。
- 答えが一つに定まらない箇所（所在を書くか、欄番号を付けるか）は、**注で必ず約束**する。
- 数値（地積・床面積）は、座標・寸法から別の方法で計算し直して一致を確認（`check_pm.py`）。
- 欄ごとに根拠条文の引用（原文照合）をつける。

### 3.5 ひっかけの型（`traps_evening`）

- 計算：C1 観測角の向き、C2 後視の読み、C3 直角に測る、C4 丸める順、C5 切捨てと四捨五入、C6 杭・塀・擁壁と筆界、C7 連鎖の検算、C8 垂線の足は真横ではない、C9 面積の条件の式、C10 公差の比較先、C11 精度区分。
- 申請書：A1 申請人、A2 添付情報、A3 登録免許税、A4 原因の日付、A5 原因の欄番号、A6 件数（一の申請か）、A7 代位・相続人、A8 抵当権・承諾書。
- 建物：D1 算入しない部分、D2 増築後の面積を一度に切り捨てる、D3 階数に数えない部分、D4 独立性、D5 附属建物の符号・主従。

## 3.6 書式ひな形の一覧と出題順（申請書の日）

- 申請書の日に出す書式は、市販講座の一覧（No.2〜77）を `forms_catalog.py` に取り込み、**過去問（H20〜R8）での出題数の目安が多いものほど先に出やすい重み付きの乱数順**（重み＝出題数＋0.3、seed固定）で並べる。順番は `schedule/forms-order.md`（自動生成）。出題数は、リポジトリの年度別記事の主題から数えた目安。
- 作成済みの書式は `forms_made.json`（No→問題ID）に登録し、問題の `registry.json` に `forms_no` を付ける。**新しい申請書は、出題順の「未作成」の先頭から作る**（`python3 daily-drill/forms_catalog.py` が先頭5つを表示する）。
- 条文で確かめられない書き方（表の行の分け方など）は、過去問の解答例の形に合わせ、注で約束する。
- **全75書式（No.2〜77、No.1・19を除く）を作成済み**（PM-02〜PM-81。2026-10-23）。PM-17以降は1問1ファイルのモジュール方式で作る：
  1. `evening/forms/pmNN.py` に `PROBLEM`（exam・calc・fig・coords・form）と `REGISTRY` を書く。部品と作り方の決まりは `evening/forms/common.py`、見本は `pm20.py`（土地）。担当の書式は `forms_plan.json`。
  2. `python3 daily-drill/evening/gen_forms.py PM-NN`（並行して作るときは `--json-only` を付け、最後に付けずに1回実行して `registry.json`・`forms_made.json` を更新）。
  3. `python3 daily-drill/check_pm.py PM-NN`（条文の原文照合、`area_checks` による面積の照合、`tax_count` による登録免許税、申請人などの住所が問題文にあるか、合筆・合体・合併の印鑑証明書）→ NG 0件。
  4. `python3 daily-drill/fit_check.py PM-NN`（問題がA4 2枚）。
  5. 独立照合：`python3 daily-drill/evening/dump_exam.py PM-NN` で答えを伏せた問題文だけを別の担当に解かせ、`--answer` で突き合わせる。指摘を直してから採用する。
- 独立照合で見つかった誤りの型（次に作るときに先に確かめる）：答えにしか書いていない住所（PM-70）、合筆・合体・合併の印鑑証明書の書き落とし、所有権の登記がある建物の合体で「所有権登記の表示」の表の欠け（PM-25）、隣の筆の座標の面積が自分の公差を超えて迷わせる設計（PM-34）、土地の問で建物の条文を挙げる取り違え（PM-53）、先例による扱いを「実務による」とぼかして答えが決まらない注（PM-73）。
- 条文で直接決まらず、先例・実務の取扱いや注の約束で答えを決めた書式（解説にその旨を書いてある）：分筆登記の抹消（PM-59）、一棟の建物の全部の滅失を一人から申請（PM-73）、当初から要件を欠く区分建物の滅失（PM-69）、分割合併の登録免許税の数え方（PM-42）、分棟の原因の文言（PM-32・45）、海没・一部海没（PM-29・35）。

## 4. 追加する型の設計（未作成。次に作る順）

### 4.1 T8 公差・精度区分の判断（優先度1）　※第1作は `PM-08` で作成済み（`evening/build_PM-08.py`。見本にする）

- **位置づけ**：計算問題の後半設問、または申請書の「登記の目的・原因」の判断として入れる。
- **設問の形**：「分筆後の地積の合計と登記記録の地積の差は、不動産登記規則第77条第5項の誤差の限度内か。地積に関する更正の登記は必要か。」答えは「必要／不要」と、その結果登記の目的が「土地分筆登記」か「土地地積更正・分筆登記」か。
- **PM-08で決めた作り方**：問題文に誤差の限度の表（甲2・甲3。登記記録の地積の行を含む）を載せる。表の値は小数第2位未満切捨て（式は (0.05＋0.01×⁴√F)×√F が甲2、甲3はその2倍。過去問記事の値と一致を確認済み）。差は「公差を少し超えるが甲3の範囲内」に設計する（甲3で比べる誤りを誘う）。登記の目的は規則第35条第7号の「土地地積更正・分筆登記」。座標は四捨五入の境目（x.xx5）から離す（作成時にassert）。
- **作り方**：精度区分（市街地地域・村落・農耕地・山林原野など）を問題文で与え、甲2・乙1などの公差を表から選ばせる。差が**公差をわずかに超える／わずかに下回る**設計にして、比較先（登記記録の地積か、分筆後の合計か。準則第72条第1項）をひっかけにする（C10・C11）。
- **原文**：規則第77条第5項（公差）、準則第72条を `laws/` で確認してから作る。

### 4.2 T9・B7 作図（優先度1）　※第1作は `PM-09`（地積測量図）・`PM-10`（建物図面・各階平面図）で作成済み（`evening/build_draw.py`、描画は `draw_forms.py`。見本にする）

- **答案用紙の様式**：地積測量図の枠（地番・所在・縮尺・方位・作成者・申請人の欄）、建物図面・各階平面図の枠を、答案用紙のとおりの大きさで解答欄に置く。
- **採点項目**：①縮尺と図の大きさ（枠に収まるか）、②辺長（小数第2位）、③境界標の種類、④方位と地番の記載、⑤基準点の名称・座標、⑥建物の位置を示す距離（所在の確認）。
- **解答**：座標から機械で描き（`figure.py` に作図関数を足す）、重なりの自動検査を行う。解答欄には自分で描く。
- **PM-09・PM-10で決めた作り方**：答案用紙は実物と同じ大きさ（枠の幅182mmで、1/250は1m＝4mm、1/500は1m＝2mm）。枠（所在・地番・縮尺・作成者〈略〉・申請人〈略〉）は印刷済み。解答ページには、座標から機械で描いた模範の作図と、規則第77条・第82条・第83条の記録事項に対応した自己採点項目（12項目・10項目）を付ける。数値の欄（辺長・地積・床面積・距離）は回答欄に先に書く。
- **評価は自己採点**のチェックリスト形式（○×を付ける項目を問題に付ける）。

### 4.3 T5・T6・T7（優先度3）と B3〜B6　※B3〜B6は書式ひな形の全作成（3.6）で作成済み。T5・T6・T7 は未作成

- 型ごとに、過去問記事（`note-articles-Kijyutsu/`）で同じ型の出題年度を読み、手順とひっかけを書き出してから作る。
- B3（合体・合併・分割・区分）は、新築・増築と同じ形式（申請書）で、登記の目的・原因・添付情報・登録免許税の違いを問う。区分建物の区分（縦割り・階層）は構造欄の屋根の種類（準則第81条第3項）も問う。
