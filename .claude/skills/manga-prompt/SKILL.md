# 4コマ解説図解プロンプトの作成・品質ゲート

規則の正本は `tools/drill/manga/MANGA_RULES.md`（サイズ・レイアウト・キャラクター・吹き出し・配色・品質ゲート）。見本は `tools/drill/manga/D0520_prompt.md`。

## 新しい肢のプロンプトを作る
1. `python3 tools/drill/drill.py explain <ID>` で正解・出典・記事の解説を読む（独自の解説・記事にない条文は入れない）。
2. **記事タイトル・冒頭文・見出し画像**：`MANGA_RULES.md` の定型で作る（タイトル＝`【土地家屋調査士受験生向け】4コマ解説図解<ID>～<出典>～`。冒頭文＝1段落目の問いかけ `lead1` ＋固定の2段落（案内・促し）。見出し画像＝`HEADERS`（タイトル2行の問いかけ・強調語・左右の場面）から（背景は苦手分析シリーズ踏襲の水彩の空に統一）自動生成）。
2b. **最初に必ず読む（最優先）**：`MANGA_RULES.md` の「4コマの目的」（出題者のひっかけ・受験者の勘違い・結論が逆になる対比を特定し、設計メモに3行で書く）と「案の型（パターン）と選び方」（第一案・第二案・第三案の型を参照して、その肢の読者の理解にいちばん役立つ構成を毎回検討する。型に固執しない）。末尾の「構成の知見ログ」の過去の知見を使い、作り終えたら今回の知見を1〜3行書き足し、`python3 tools/drill/manga/pattern_audit.py` で型の使用状況と整理の時期を確かめる。既存の型で説明しきれない新しい構成ができたら、先に「型の一覧」へ登録する（未登録の型名は検査がNG）。整理の手順は「型の登録と整理の仕組み」。
3. **構成表の組み方（題材ごとにコマの使い方を選ぶ）**：`MANGA_RULES.md` の「構成表（文言の正本）の組み方パターン集」で題材のタイプ（A時点・B当事者・C概念の区別・D数量・E原則例外・F手続）を決め、5点（問いの事案・出題者のねらい・ひっかけ・勘違い・正しい整理）を図や文言として置く。コマごとの`chars`（faces／small／tori／aiko／none）は並びを変え、定型の「思い込み→カード→対比→結論」に当てはめない。
3b. **工程A（設計）**：登場人物の台帳（初出のコマを決める）、矢印の意味の台帳（取引／効力／手続を同じ鎖でつながない）、会話の順序（藍子の質問→トリ先生の答え）、配色（はい・○＝青、いいえ・×＝赤、中立＝ネイビー。他の色名や色の選択指示・否定は書かない）。
4. `tools/drill/manga/manga_specs.py` に設計データ（工程Aの内容）を足し、`python3 tools/drill/manga/gen_prompts.py <ID>` で `<ID>_prompt.md`（構成表＋```text のプロンプト＋検品チェック。見本は `D0520_prompt.md`）を生成する。
4b. **一発合格ルール**：新しい肢の設計データには `ippatsu=True` を付ける。`MANGA_RULES.md` の「一発合格のための作成ルール」（A内容・B色・C キャラ・D文字・E手順）に従い、図の部品ごとの色・並べ方・大きさを先に決め、正しい整理には理由を1行入れる。字が崩れた語は `check_prompt.py` の `GARBLED` に登録する。
5. **工程B**：`python3 tools/drill/manga/check_prompt.py tools/drill/manga/<ID>_prompt.md` を実行し、**NG 0件**にする。WARNは理由を確認する。
6. **工程C（目視レビュー）**：①初見の読者テスト（全ノード・全矢印の始点→終点の意味を1行で言えるか）、②構成表の全文言を記事と1つずつ突き合わせ、③対比カードの極性。結果をユーザーに要約して報告してから、プロンプトを渡す。

## 文字の誤字を防ぐ（HTML描画版）
画像生成AIの画像に誤字があった、または文言の正確さが最優先の肢は、`tools/drill/manga/render/render_manga.py <layoutの名前>` で文字を固定フォントで描く（`MANGA_RULES.md` の「文字を崩さない描き方」）。構成表の正本から台詞・タイトルを読み、図の中身は `render/layouts/<名前>.py` に構造化して書く。キャラクターの素材は `render/SPRITES.md`。

## 生成画像のファイル名
保存時は `MANGA_RULES.md` の「画像ファイル名」に従う（本文用＝`4コマ解説図解<ID>～<出典>～.<拡張子>`、見出し＝`…_見出し.<拡張子>`、途中の版＝`_v01` など）。

## 生成画像の検品（ユーザーが画像を見せたとき）
構成表と一字ずつ照合 → 吹き出しの尾・立ち位置（藍子＝左、トリ先生＝右）・会話順 → 色（青＝はい、赤＝いいえ）・流れ図の意味 → 法的正確性。不具合があれば（共通の原因なら生成器・`check_prompt.py`・規則に入れる。個別の `final_extra` で済ませない）「検品結果と修正依頼文」（直前版基準・変更前/後・変更しない箇所）を `<ID>_prompt.md` の末尾に残す。`check_prompt.py` を再実行し、新種の不具合は `MANGA_RULES.md` の品質ゲートと `check_prompt.py` の両方に追加する。

## コマのキャラクター配置
図解・フローチャート・暗記事項を大きく見せたいコマは、設計データの `chars`（`aiko`／`tori`／`small`／`faces`／`none`）で、キャラクターを片方だけ、または非常に小さくしてよい（`MANGA_RULES.md` の「キャラクター」）。1コマ目・4コマ目は原則として両方登場させる。

## プロンプトを直すとき（本体の同期。必ずこの順）
ユーザーから「プロンプトを直して」「この画像のここを直して」と言われたら、`<ID>_prompt.md` を手で直さない。①`manga_specs.py`（または共通なら `gen_prompts.py`）を直す → ②`gen_prompts.py [<ID>]` で再生成 → ③`check_prompt.py` NG 0件 → ④`gen_prompts.py --check` が「不一致 0件」 → ⑤`rev`・`ver` を更新 → ⑥コミットしてpush。詳細は `MANGA_RULES.md` の「プロンプトを直したら、各記事のプロンプト本体も更新する」。藍子の人体構造・ポーズの指示は全プロンプトに入っている（`MANGA_RULES.md` の「藍子の描写ルール」）。

## 守ること
- 正誤はバンク（`data/items.json`）の値、解説は origin/main の記事。記事は編集しない。
- 変更は `tools/drill/manga/` と本スキルのみ。コミットして指定ブランチにpushする。
