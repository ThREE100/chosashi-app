# 択一式 一問一答ドリル（運営指示書・2026-10-05改訂）

エンジンは `python3 tools/drill/drill.py`。記録は専用ブランチ `drill-log`（worktree `.drill-log/`：log.jsonl・tags.jsonl・issues.jsonl・session.json・focus.json）。
**正誤の判定はスクリプトの出力だけを正とし、自分の法律知識で変えない。** 基準は現行法令（mainのnote-articlesの結論）で、出題当時の公式正答とは違うことがある。

## 1. 基本の流れ（5問1セット）
1. 開始：`drill.py start`（記録ブランチ用意、origin/mainの最新取得、進捗表示）。「記事の参照元」「mainで更新された記事」の警告があれば伝える。
2. 出題：`drill.py next -n 5`。**5問まとめて**、次の形式で出す（スマホ向けに前置きは書かない）。
   - `[1/5] 〔論点〕【法令】肢の文`（復習の肢は復習であることを添える）。
   - 末尾に「回答は y（〇）・n（×）・d（？）の5文字で」。
   - 通算の問題番号（例：641〜645問目）と、フォーカス中は残り問数を添える。
3. 回答：ユーザーは5文字（例 `nydnn`）で返す。
   - まず**読み取り結果を1行で復唱**（例：1問目×、2問目〇…）。
   - 文字数が5でなければ、記録せず再送を求める。同じセットに複数回答があれば最後の入力を採用。
   - 入力：y=〇、n=×、d=？（大文字小文字不問）。〇×？・o/x/? も可。数字は回答として扱わない。
   - 肢ごとに `drill.py answer <ID> <o|x|?>` を実行し、5問後に `drill.py save`（push）。
4. 結果報告（1セットごと）：
   - 表（#、問題の要旨、あなたの回答、正解、判定 ✅定着／❌誤解／❔未習得）。
   - 誤解・？の肢は、`answer` 出力の【記事の解説】の要点を、記事の文言から外れずに短く整理する（出典ID・対比IDも添える）。
   - 条文照合の指摘があれば伝える（下記3）。なければ「指摘なし」と一言。
   - 続けて次の5問を出す。ユーザーが「次」と言えば同じ流れ。
5. 終了時：`drill.py report` の要点（弱い論点上位、誤解が多い論点、〇×の癖）を3〜5行で。「苦手分析」と言われたら `report` を詳しく読み解き、次に取り組む論点を提案する。
- 科目指定：`--subject 民法|不動産登記法|調査士法`、論点：`--topic`、弱点集中：`--mode weak`、復習のみ：`--mode review`。

## 2. 解説のルール
- 解説は **origin/main の `note-articles/`** の該当肢の解説の**そのままの引用**（`answer`・`explain` の出力）。言い換え・要約の置き換え・独自の解説・自分の知識による理由づけは禁止。
- 「？」は責めない。正解と引用した解説を見せて次へ。
- 対比（pair）があれば、そのIDだけ一言で触れる（求められたら `explain <対比のID>`）。「解説」と言われたら `explain <ID>`。
- `status` が provisional の肢は「（正誤の根拠が弱い問題）」と添える。hold は出題しない（`REVIEW_HOLD.md`）。
- 引用した解説に誤りがあると気づいたら、その場で指摘し訂正案を添える（`drill.py issue <ID> "問題点" --proposal "訂正案"`）。一覧は `drill.py checks`。

## 3. 条文照合（事前照合済み）
- 全肢の解説は `note-articles/laws/` と照合済み（`data/article_checks.json`）。**出題のたびに条文を確認し直さない。**
- 指摘が出た肢は `answer`・`explain` が自動で **`#article-fix`** タグを付ける。「🏷 自動タグ付け」と出たら一言伝える。一覧：`drill.py tags article-fix`。
- 【条文照合】に指摘が出たときだけ、問題点・原文・訂正案（提案）を伝える。`unverified` は「誤り」と言い換えない。判定（バンクの値）は変えない。
- 「照合のあとにmainで更新されています」の警告は再照合が必要という意味。再照合したら `merge_checks.py` を再実行する。

## 4. 編集・push の権限
- **`note-articles/` の記事は、ユーザーの明示の指示があるときだけ編集する**（指摘と訂正案の提示まで。`#article-fix` は後で一括修正）。記事を直したら、`tools/drill/work/article_check_*.json` の該当指摘を外して `merge_checks.py` を再実行し、`#article-fix` を `untag` する。
- バンク（`data/items.json`）の値は会話中に変えない（変更はユーザー指示があったときだけ。問題文を改題した記事は、バンクも合わせる）。
- ドリルの変更（`tools/drill/`・このスキル・`CLAUDE.md`）は、ユーザーの指示なしに `main` へ push してよい。push 前に `git pull origin main`。
- 苦手分析シリーズ（note-articles/column/）の執筆は別チャットの作業。ここでは材料（JSON）を出すだけ。

## 5. 判定と復習のルール
- 〇/×が正解＝定着、〇/×が不正解＝誤解（逆に覚えている）、？＝未習得。誤解は未習得より重い。
- 誤答・？は連続正解数0に戻り、**日付をまたいだ翌日（日本時間0時）以降**に復習に出る（同日の再出題はない。「また出ます」と言わない）。以降の間隔は1・1・3・7・21・60日。初見で正解した肢は21日後に確認、連続6回で卒業。
- 新規は、未着手の論点を先に、次に弱い論点・出題頻度の高い肢を優先。
- **復習比率**：全肢（約2,100）を1周し終えるまでは、mixed の復習は5問中1問まで。1周後は最大半分。
- **誤解の訂正**：「〇×は合っていたが理解が違った」と言われたら `drill.py mark <ID> miscon --note "理由"`。戻すなら `mark <ID> known`。
- **タグ**：あとで一括呼び出ししたい肢は `drill.py tag <ID> nigate --note "理由"`、一覧 `tags nigate`、解除 `untag`。

## 6. 出題フォーカス（科目・論点の一時除外）
`drill.py focus on --exclude-subject 民法 --exclude-topic 区分建物・敷地権・共用部分 --count 100`：除外した科目・論点を新規・復習とも出さずに指定問数を出題。復習の期限・間隔は変えず、除外分の復習はフォーカス終了後に出る。回答1件ごとに残りが減り、0で自動解除されて全分野ランダムに戻る。`focus status` / `focus off`。`--subject`・`--topic` 指定の出題にはかけない。

## 7. 記録・分析の運営
- 回答は1問ごとに必ず `answer` で残す（ユーザーの返答を補完しない）。5問ごとに `save`。
- 苦手分析の材料は `tools/drill/analysis/` にJSONで出力する（統計、勘違いのポイント、必要知識、判定フロー案、図解案、肢ごとの履歴・記事パス・条文照合、編集者向けメモ）。
- 正答率などの集計は `drill.py report` と記録（log.jsonl）から出す。
