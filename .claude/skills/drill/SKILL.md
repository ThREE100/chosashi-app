# 択一式 一問一答ドリル

回答は **〇・×・？** の3択（？＝わからない）。記録は専用ブランチ `drill-log` の `log.jsonl`。
エンジンは `python3 tools/drill/drill.py`。**正誤の判定はこのスクリプトの出力だけを正とし、自分の法律知識で変えない。** 正誤の基準は現行法令（note-articlesの解説記事の結論）で、出題当時の公式正答とは違うことがある。

## 手順
1. 開始: `python3 tools/drill/drill.py start`（記録ブランチを用意し、**origin/mainの最新を取得**して、進捗を表示）。結果を1〜2行で伝える。
   「記事の参照元」の行（取得できたか／古い版を参照していないか）と、「mainで更新された記事」の警告があれば、それも伝える。
2. 出題: `python3 tools/drill/drill.py next -n 10`（既定は復習と新規の混合）。
   - ユーザーが科目を指定したら `--subject 民法|不動産登記法|調査士法`、論点なら `--topic`、
     弱点集中なら `--mode weak`、復習のみ `--mode review`。
3. **1問ずつ**出す。出力は短く:  `Q3/10〔科目／論点〕` ＋ 肢の文 ＋ 「〇 / × / ？」。スマホなので長い前置きはしない。
4. ユーザーが 〇/×/？ を返したら、すぐ `python3 tools/drill/drill.py answer <ID> <o|x|?>` を実行する。
   出力の 正誤・出典・【記事の解説】 を、**そのまま**返してから次の問題へ。
   - 【記事の解説】は note-articles（main）の該当肢の解説の**引用**。**言い換え・要約・補足・独自の説明は禁止**。自分の法律知識で解答や理由を作らない。
   - 「？」は責めない。正解と引用した解説を見せて次へ。
   - 対比（pair）があれば、その肢のIDだけ一言で触れる（理由は付けない。求められたら `explain <対比のID>` の引用を出す）。
   - 「解説」と言われたら `drill.py explain <ID>`（全出典の引用）を出す。
5. 10問ごと、または「終わり」で `python3 tools/drill/drill.py save`（push）。途中で切れても失われないよう、
   5問ごとに save してよい。
6. 終了時に `python3 tools/drill/drill.py report` の要点（弱い論点の上位、誤解が多い論点、〇×の癖）を3〜5行で。
   ユーザーが「苦手分析」と言ったら `report` を詳しく読み解き、次に取り組む論点を提案する。

## 解説の誤りの扱い（事前照合済み）
- 全肢の解説は、あらかじめ `note-articles/laws/` の原文と照合してある（`data/article_checks.json`）。**出題のたびに、自分で条文を確認し直さない**（時間がかかるため）。
- 条文照合に指摘が出た肢は、`answer`・`explain` が**自動で `#article-fix`（記事修正対象）のタグ**を付ける（同じ肢に重複しない。記事が照合後にmainで更新されている場合は付けない）。「🏷 記事修正対象として自動タグ付けしました」と出たら、そのことをユーザーに一言伝える。後でまとめて直すときは `drill.py tags article-fix`。記事そのものは、ユーザーの指示があるまで編集しない。
- `answer`・`explain` の出力に【条文照合（事前確認）】の指摘が出たときだけ、その内容（問題点・照合した原文・訂正案〔提案〕）を、そのまま分かりやすく伝える。
  - 「指摘なし」「未実施」と出たら、何も足さない。
  - 指摘の `unverified`（確認できない）は「誤り」と言い換えない。
  - 正誤の判定そのものは変えない（バンクの値が正）。
- ユーザーから「この解説は正しいか」と聞かれたときだけ、`laws/` で追加確認する。確認できないことは、確認できないと言う。
- ユーザーの求めがあれば `drill.py issue <ID> "問題点" --proposal "訂正案"` で記録する。一覧は `drill.py checks`。

## 訂正・タグ
- ユーザーが「〇×は合っていたが理解が間違っていた」と言ったら、`drill.py mark <ID> miscon --note "理由"` で誤解扱いに訂正する（翌日以降の復習に出る）。
- 「苦手分析シリーズの候補」など、あとで一括で呼び出したい肢は `drill.py tag <ID> nigate --note "理由"`（タグ名は nigate）。
  一覧は `drill.py tags nigate`（`--json` も可）。タグは記録ブランチ drill-log の tags.jsonl に保存され、`save` で push される。
- タグの解除は `drill.py untag <ID> nigate`。判定を戻すには `drill.py mark <ID> known`。

## 記事の参照元と編集の禁止
- 解説の引用は、**origin/main の `note-articles/`** から読む（`git show origin/main:…`）。作業ツリーのコピーは使わない（取得できないときだけローカルにフォールバックし、警告が出る）。
- **`note-articles/` の記事は編集しない**（修正が必要なときは、指摘と訂正案の提示までにとどめ、ユーザーの指示を待つ）。
- 照合結果は、照合した時点の記事の版に対するもの。記事がmainで更新されると「照合のあとにmainで更新されています」と警告が出る（再照合が必要）。

## 注意
- 誤解・？の肢の復習は、日付をまたいだ翌日（日本時間0時）以降に出る。同じ日の再出題は仕様上ない（「また出ます」と言わない）。
- 記録の回答は 1問ごとに必ず `answer` で残す（ユーザーの返答を勝手に補完しない）。
- `status` が provisional の肢は根拠が弱い。出題時に「（正誤の根拠が弱い問題）」と添える。
- 法改正に関する注記は、記事の解説に書かれている。引用をそのまま出す。


## 出題の復習比率（2026-10-05ユーザー指示）

全肢を1周解き終える（未出題が0になる）まで、`drill.py next`（mixed）は復習を5問中1問までに制限する（実装済み）。1周完了後は従来どおり最大半分。
