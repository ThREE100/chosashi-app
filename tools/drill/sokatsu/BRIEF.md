# 直前期「苦手論点つぶし総合記事」章執筆ブリーフ（全担当共通）

## 背景
土地家屋調査士試験・択一式の一問一答ドリルで、同じ肢を何度も間違えている（または「？」と答えた）449肢が復習対象になっている。
これを **民法／不動産登記法／土地家屋調査士法** の3本の総合記事にまとめる。直前期に一気読みする記事なので長くてよいが、**同じ論点・似た論点は1つの論点にまとめて統合解説**し、肢ごとにバラバラに説明しない。
あなたは、そのうちの **1つの章（担当グループ）** を書く。他の章は別担当が並行して書く。

## 入力（担当グループのバンドル）
- `dos/bundle_<CODE>.txt` … 担当肢の一覧。肢ごとに ID・バンクの正解（〇正しい記述／×誤った記述）・回答履歴・誤答通算W・出典・肢の文・**記事の解説（note-articlesからの引用）**・未処理の条文照合指摘が入っている。
- `dos/bundle_<CODE>.json` … 同じ内容の機械可読版。
- 法令の原文：`/home/user/chosashi-app/note-articles/laws/`（不動産登記法 `fudousan-touki-hou.md`、令 `fudousan-touki-rei.md`・別表 `fudousan-touki-rei-betsuhyou.md`、規則 `fudousan-touki-kisoku-1/2/3.md`、準則 `fudousan-touki-jimu-junsoku.md`、区分所有法 `kubunshoyuu-hou.md`、民法 `minpou-1-soukyoku-bukken.md`・`minpou-2-saiken.md`・`minpou-3-shinzoku-souzoku.md`、調査士法 `chousashi-hou.md`・施行規則 `chousashi-hou-sekourule.md`、登録免許税法 `touroku-menkyozei-hou.md` ほか）。条文番号・数字を書くときは `grep` で原文を確かめる。
- 既存の関連記事（もっと詳しく読みたい人向けの参照先として、本文末に `関連記事:` で最大3本まで挙げてよい。ファイルは必ず `ls` で実在を確かめる）：`/home/user/chosashi-app/note-articles/column/nigate-*.md`（苦手分析シリーズ①〜㉔）、`/home/user/chosashi-app/note-articles/topics/*.md`、`/home/user/chosashi-app/note-articles/column/*.md`。

## 絶対に守る正確性のルール
1. **〇×の正解はバンクの値が正**。自分の知識で変えない。肢の「正誤の理由」は、バンドルの「記事の解説」の結論に従う。
2. 記事の解説が「根拠を確認できていません」「実務上の取扱いによる整理です」と注記している箇所は、**その注記どおり**に書く（先例・通達を創作しない）。
3. 追加する条文番号・期間・金額・要件は、`note-articles/laws/` の原文で確かめてから書く。確かめられないものは書かない。**現行法**で書く（出題当時の旧条文・旧用語〔例：時効の「中断」〕は「出題当時は〜」と短く触れてよい）。
4. 「⚠条文照合の未処理指摘」が付いた肢は、指摘と原文を読んで、**正しい側**で説明する。迷ったら担当の最後に `<CODE>_notes.md` へ「要確認」として書く（記事本文は断定を避ける）。
5. 判例番号（最判昭◯◯）・先例番号・通達番号・専門誌の巻号は書かない（内容の言及は可）。

## 記事の体裁（note向け。既存記事のルール）
- 敬体（です・ます調）。見出しは体言止め可。箇条書きの末尾は体言止め可。
- **Markdownの表（`|…|`）は使わない**。比較は箇条書きで。
- 文中の注釈括弧は全角（）。条文の引用は「」。
- 「たとえば」の具体例を、抽象的な説明のあとに必ず1つは入れる（登記の場面でも民法の場面でも、実際の事例で）。
- 初学者にも読めるが、直前期の受験生が一気読みする前提で、**結論 → 理由 → 判断のしかた** の順。冗長な前置きは書かない。
- 記事内で「ドリル」「一問一答アプリ」「記録」「復習対象」などの語を使わない。学習履歴に触れるのは後述の「誤答の傾向」でだけ、「この論点では〇回逆に答えた」という言い方で簡潔に。日付や自分の回答の具体的な日付は書かない。

## 章の構成（この形で `out/<CODE>.md` に書く）
```
### {章タイトル}（担当グループの内容を一言で）

**この章の対象**：{N}肢。{論点の数}の論点にまとめています。
**この章の誤りの傾向**：（3〜6文。〇を×にした／×を〇にした肢の数、「？」の数、誤答の原因タグの多いもの上位2〜3つとその意味。数字は `<CODE>_tags.json` と肢ごとの履歴から数えた実数）

#### 【{CODE}-1】{論点の見出し。「〜は〜か」という問いか、結論の形にする}
**この論点で出た肢**：D0001・D0002・…（IDのみ。出典は肢ごとの判定の行に書く）
**結論**：（1〜3文。この論点の核心）
**中身の整理**：（箇条書きを中心に、条文・要件・例外・数字・主体を整理。似た制度は「Aは〜、Bは〜」と対比して並べる。ここが解説の本体）
**たとえば**：（具体例1つ）
**なぜ繰り返し間違えるのか**：（この論点の肢の履歴と内容から、「考えられる原因」を2〜5文で。どの方向に間違えたか〔正しい記述を×／誤りを〇／「？」〕、原因タグ（下記）の名前を文中に自然に出す。推測であることがわかる書き方にする）
**判断のしかた**：（問題文を見て何を確認するか。1)2)3)の手順、または覚え方）
**肢ごとの判定**：
- D0001 〇 肢の要旨（30〜50字）。→ 理由を一言（15〜40字）。★誤答3回（誤答通算Wが2以上の肢だけ「★誤答W回」を付ける）
- D0002 × …
（バンドルの全肢を、**いずれか1つの論点に、ちょうど1回**、この形式の行で書く。行頭は必ず `- D0000 〇` または `- D0000 ×`。〇×はバンクの正解。）

（論点を必要なだけ繰り返す）

**この章の直前チェック**：
- （この章で絶対に落とさない一行知識を5〜10個。対比の形で）
```
- 論点のまとめ方：条文・制度・場面が同じ肢、結論が対になっている肢（pair）は同じ論点に入れる。1論点に3〜8肢が目安。1肢しかない論点は作らず、近い論点に合流させる（どうしても独立する場合のみ）。
- 論点の並び順：基本→応用、頻出順。
- 肢の数が多くても、すべてを丁寧に書く。ただし字数の目安は **全体で {肢の数}×300字 ±25%**（肢ごとの判定の行を含む）。

## 原因タグ（`<CODE>_tags.json` に肢ごとに付ける。肢ごとに primary を1つ、必要なら secondary を1つ）
- `A` 原則と例外の取り違え（例外・ただし書・特則の見落とし）
- `B` 主体の取り違え（誰が・誰に・誰の名義で）
- `C` 時点・期間・基準の取り違え（いつの状態か、何か月以内か、起算点）
- `D` 似た制度・似た登記との混同（対比で覚えていない）
- `E` 要件の欠落または過剰（足りない要件／要らない要件）
- `F` 数字・文言の暗記不足（期間、金額、保存期間、通知先、書面の名前）
- `G` 一般化のしすぎ・限定語の見落とし（常に・必ず・のみ・いずれも）
- `H` 前提・事例の読み違い（図、事例の設定、限定条件）
- `I` 知識の空白（制度そのものを知らず「？」。初見で歯が立たなかった）
- `J` 結論の向きの逆転（できる／できない、有効／無効、対抗できる／できない を逆に覚えている）

`<CODE>_tags.json` の形：`{"D0001": {"primary": "A", "secondary": "J", "group": "{CODE}-1"}, ...}`。バンドルの全肢をちょうど1回ずつ。

## 作業の流れ
1. バンドルを全部読む（`dos/bundle_<CODE>.txt`）。
2. 論点にグルーピングする（先にメモしてよい）。
3. 必要な条文を `note-articles/laws/` で確認する。
4. `out/<CODE>.md` と `out/<CODE>_tags.json` を書く（Write）。
5. `python3 /tmp/sokatsu_work/check_cov.py <CODE>` を実行して、欠落・重複・正誤不一致・体裁の警告が0件になるまで直す。
6. 「要確認」（記事の解説と条文のずれ、断定できなかった点）があれば `out/<CODE>_notes.md` に短く書く。なければ作らない。
7. 最終報告は短く（200字以内）：書いたファイル、肢数、論点数、文字数、要確認の有無。

## 書き方で避けること
- 記事の解説をほぼそのまま写して肢ごとに並べるだけにしない。論点ごとに**統合して**説明する。
- 「〜と考えられます」の連発で逃げない。結論は断定する（根拠が弱い箇所だけ、記事の注記どおりに留保する）。
- 肢の要旨を書き換えて意味を変えない。事例の肢は、登場人物（A・B・C）と結論がわかる形で要旨を書く。
- 原因分析は**肢の内容と履歴から合理的に推測できる範囲**で。「あなたは〇〇が苦手」と決めつけない。
