## 作り方・守ったこと

- **図解**（`src/gen_infographic.py`）：`note-articles/infographic-prompt-template.md` と `joubun-nigate/common/infographic_parts.py` の共通部品（簡体字対策・背景の不透明化・最終確認）で組み立てた。この章の図解は「誰が・いつまでに・何を添えるか」の分類と、手続の流れ・申請人の仕分けが中心で、はい／いいえの分岐ではないため、青・赤は使わず、濃紺・薄い灰色・薄い黄色のマーカーで描く指示にした（はい＝青・いいえ＝赤の規則は、はい／いいえの分かれ道を描く図を作るときのためのもので、この章には該当する図がない）。画像の中には、図の番号・問題番号・個人の演習結果（誤答の回数など）を入れない。
- **4コマ**（`src/spec_4koma_PG2-*.py` → `src/build_4koma.py`）：`tools/drill/manga/MANGA_RULES.md` の設計メモ（出題者のひっかけ・受験者の勘違い・対比する制度・型の選び方）を書き、生成器 `gen_prompts.py` の `render()` で作って `check_prompt.py` で NG 0件・WARN 0件にした。型は肢ごとに検討した。4コマ1・4コマ4＝型5（整理カード併用。型1の思い込みと組み合わせ。列挙・手続の記憶が肝）、4コマ2・4コマ5＝型3（理由の説明。型5の整理カードを併用。『なぜ承諾のない側にだけ残るのか』『なぜ名義人になってから義務が生じるのか』）、4コマ3・4コマ6＝型4（複数肢の対比。型5の整理カードを併用。同じ事例から枝分かれする2肢を1本にまとめた）。単独のnote記事用の節（記事タイトル・冒頭文・見出し画像）は、総合記事に差し込むため外し、保存名を足した（見本と同じ体裁）。結論帯の問題番号は載せる。登場人物はトリ先生と藍子だけで、事例の当事者は文字のカード（Ａ・Ｂなどの記号は使わない）。HTML描画版は使っていない。
- **条文**：画像に載せた条文の語は、`note-articles/laws/` の原文（`fudousan-touki-hou.md`、`fudousan-touki-rei-betsuhyou.md`、`fudousan-touki-kisoku-1.md`、`fudousan-touki-jimu-junsoku.md`、`kubunshoyuu-hou.md`）と照合した（`src/check_all.py`）。
- **記事から外れないこと**：図・セリフは記事の結論・用語の範囲。記事が「実務の取扱い」「条文に明記なし」とした点は、画像の中でもそう書いて断定していない。出題当時の言い方との違いは、肢を解く決め手にならないので入れていない。
- **4コマにしなかった肢**：D0378・D0379（階層の表示・柱の求積。実務の取扱いで条文の対比がなく、図解2で足りる）、D1991（併せて申請。図解6で扱う）、D0885（図面の要否。図解9）、D1702・D0797（団地共用部分・公正証書。図解11）。誤答が多い順と、結論が逆になりやすい対比の有無で優先した。
