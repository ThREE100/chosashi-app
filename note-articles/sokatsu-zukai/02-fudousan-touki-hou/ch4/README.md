## 作り方・守ったこと

- **図解**（`src/gen_infographic.py`）：`note-articles/infographic-prompt-template.md` と `joubun-nigate/common/infographic_parts.py` の共通部品（簡体字対策・背景の不透明化・最終確認）で組み立てた。この章の図解は『申請できるか』『合筆できるか』『要るか』の分類が中心で、はい／いいえの分岐ではないため、青・赤は使わず、濃紺・薄い灰色・薄い黄色のマーカーで描く指示にした（図解1〜6・8〜14）。はい／いいえの判定の流れ図は図解7（分筆を錯誤で戻せる？）の1枚だけで、はい＝青、いいえ＝赤。画像の中には、図の番号・問題番号・個人の演習結果（誤答の回数など）を入れていない。樹形図の意味の「決定木」「判定木」「ツリー」などの語は使っていない（`判定の流れ図` と書いた）。
- **4コマ**（`src/spec_4koma_PD-*.py` → `src/build_4koma.py`）：`tools/drill/manga/MANGA_RULES.md` の設計メモ（出題者のひっかけ・受験者の勘違い・対比する制度・型の選び方）を肢ごとに書き、生成器 `gen_prompts.py` の `render()` で作って `check_prompt.py` で NG 0件・WARN 0件にした。型は肢ごとに検討した：4コマ1＝型3（なぜ許可が要らないかの理由カード）、4コマ2＝型2（面積→現況→桁の3ステップ）、4コマ3＝型5＋型4（規則105条の4つの整理カード）、4コマ4＝型5（同一の5点の整理カード）、4コマ5＝型3＋型4（判決⇔実体的権利の理由カード）、4コマ6＝型3＋型1（変更⇔更正の理由カード）。単独のnote記事用の節（記事タイトル・冒頭文・見出し画像・画像ファイル名）は、総合記事に差し込むため外し、保存名を足した（調査士法編と同じ体裁）。結論帯の問題番号は載せる。
- **条文**：画像に載せた条文の語は、`note-articles/laws/` の原文（不動産登記法、令、令別表、規則、民法）と照合した（`src/check_all.py`）。
- **記事から外れないこと**：図・セリフは記事の結論・用語の範囲。出題当時の言い方と今の言い方の違い（相続財産の管理人／清算人、会社法人等番号の制度ができる前の添付書類）は、肢を解く決め手にならないので画像に入れていない。
- **既存の再利用**：付録の7肢は、すべて既存の4コマがあったため新作していない。

## 確認事項（ユーザーに見てほしい点）

- 画像の生成・目視確認は未実施（この表の全プロンプトが対象）。
- 記事が『条文に明記なし』『実務の取扱い』としている点は、画像でも断定せず、その旨を小さな帯・タグで添えた：
  - 図解6（根拠欄「実務の取扱い」）：差押えは承諾で消せない／図解9（下の帯）：仮登記・敷地権である旨の登記は合筆できない／図解8：現況の地目が違えば合筆できない／図解11：破産手続開始の登記は終結の登記があれば抹消せず合筆できる／図解7（小さなタグ「右の扱いは、実務の取扱いによる整理」）：権利を消した分筆は錯誤だけでは抹消できない／図解4・4コマ2：造成工事中の畑は畑のまま（現況主義からの整理）／4コマ1：分筆・合筆は管理の範囲（条文に明記なし）。
  - 図解2：共有地の分筆を持分の過半数で申請できるという実務の取扱いは、条文に明記がなく、結論も変わらない（ちょうど半分は過半数でない）ので、図に入れていない。
- 記事にない整理を法令DBから足した点：規則105条の4つのうち4号（鉱害賠償登録）は、肢の記事が1号〜3号にしか触れていないので法令DB（`fudousan-touki-kisoku-1.md` 第105条）由来（図解9・4コマ3）。法37条2項（変更があった後に名義人となった者は、登記の日から1か月以内）は、4コマ6の設計メモ（出題者のひっかけの説明）にだけ書き、図には入れていない。
- 4コマ6本の `記事に無い条文（ユーザー指示で追加）` の節は、生成器の固定の見出しです。中身は、肢の記事にある条文の確認メモと、法令DBで確かめた条文の出典メモです（ユーザー指示で追加したものではありません）。
- 4コマ1（D1668・D0530）は、肢の文言どおり「管理人」と書き、「相続財産の清算人」への呼称の変更（現行民法）は決め手にならないので入れていない。
- 4コマ4（D0527・D0750）の『同一の5点』は、規則105条2号の文言（登記の目的、申請の受付の年月日及び受付番号、登記原因及びその日付）を数えたもの。
- 図解7の配色：判定の流れ図の「はい」は『分筆のとき、権利を消す承諾の情報を出していないか？』に対する「はい」（＝青、錯誤で抹消できる）です。青・赤は、結論の良し悪しではなく、はい／いいえの分岐の色です。
- 保存先ブランチ：このセッションの作業ブランチ（`claude/sharp-darwin-8llean`）に保存した。`CLAUDE.md` では、4コマの作業・保存先は `main` のみとされているため、`main` へ取り込むかどうかを確認してください（この作業ではgitを操作していません）。
