# 指示プロンプト：章の記事の「論点ごと」に4コマ解説図解のプロンプトをそろえる

総合記事（直前期の苦手論点つぶし）の章の記事について、**4コマ解説図解が足りない論点に4コマのプロンプトを作り、保存し、並びを記事の順に整える**作業の指示プロンプトです。
別のセッション（Claude Code）に、下の「貼り付ける指示」をそのまま貼り、`【対象ファイル】` の1行だけ書き換えて使います（2026-10-13。不動産登記法編 第1章で実施した手順がもとです）。

---

## 貼り付ける指示

```text
【対象ファイル】note-articles/column/sokatsu-02-fudousan-touki-hou-ch◯.md

上の章の記事について、この章の論点（記事の【P○-n】の見出し）ごとに、4コマ漫画化の解説画像プロンプトを作成して、GitHubに保存してください。
すでに作成済みの4コマはそのままにして（セリフ・図・設計メモは変えない）、4コマの並び（ファイル名・通し番号・READMEの順）を記事の順序に整えてください。

## 0. 準備
- CLAUDE.md を読む（特に「4コマの作業・保存先は main のみ」「条文別『苦手克服』・総合記事の図解のルール」）。作業は main ブランチで行い、push の前に `git pull origin main` で最新化する。
- 対象の記事を最初から最後まで読む（論点の見出し、「肢ごとの判定」、章の冒頭の傾向、直前チェック）。
- この章の既存の成果物を読む：`note-articles/sokatsu-zukai/<科目>/ch◯/`（README.md、prompt_4koma_*.md、src/ の build_4koma.py・specs_4koma.py・spec_4koma_*.py・check_all.py）。
  フォルダがない章は、同じ科目の別の章のフォルダ（例：02-fudousan-touki-hou/ch1/）を雛形にして新しく作る（作る前に、ユーザーに確認する）。
- 規則を読む：tools/drill/manga/MANGA_RULES.md（冒頭の「4コマの目的」「案の型と選び方」、禁止語、配色、登場人物の初出）、tools/drill/manga/gen_prompts.py（render() の入力仕様）、tools/drill/manga/check_prompt.py、.claude/skills/manga-prompt/SKILL.md。

## 1. どの論点に4コマを作るか
- 記事の論点ごとに、次のどれで4コマがあるかを表にする：
  (a) この章のフォルダに作成済みの4コマ（prompt_4koma_*.md）
  (b) 既存の4コマを再利用（README に「既存（再利用）」と書いてあるもの：tools/drill/manga/D*_prompt.md、note-articles/joubun-nigate/ 配下）
  (c) まだない
- (c) の論点だけ、新しく4コマを作る。(a)(b) は触らない。
- 1論点につき4コマ1本。肢は、記事の「肢ごとの判定」から、受験者が結論を取り違えやすく、4コマで決め手を示せるもの（1〜3肢を1本にまとめてよい）を選ぶ。肢の正誤・出典・解説は tools/drill/data/items.json と記事で確かめる（バンクの正誤を正とし、自分で変えない）。
  穴埋めや用語の暗記が中心の論点も、対比が立つ肢（結論が逆になる組、似た語の入れ替え）を選んで作る。

## 2. 新しい4コマの作り方（設計データ）
- 1論点につき1ファイル：`src/spec_4koma_P○-NN_01.py`（NN は論点番号を2桁にそろえる。例 PA-01、PA-09）。SPEC と HEADER を、同じ章の既存の spec と同じ形式・同じ粒度で書く。
  fid は肢IDをハイフンでつないだ文字列（例 "D0929-D0930-D0931"）。型は MANGA_RULES の「案の型と選び方」を検討して選ぶ。
- 論点の数が多いときは、論点ごとにサブエージェントを並列に走らせてよい。その場合は、各エージェントが書くのは自分の spec ファイル1つだけにし（build_4koma.py の NAMES など共有ファイルは、取りまとめ側が登録する）、各自がスクラッチで gen_prompts.render(spec) → check_prompt.py を通して NG 0件・WARN 0件にしてから報告させる。
- 肢IDのタグ（作成済みの4コマと同じ形に必ずそろえる）：
  1. 結論帯の2行目：`問題D○○○○・D○○○○　正解〇・×（出典 例 H27-Q04イ・ウ）`（band2。必ず入れる）
  2. コマ1の表・カードの小タグ：`肢D○○○○`（肢が複数なら1肢ごとに1枚／1行。肢が1つだけなら、疑問のバッジを `肢D○○○○：○○は、…？` の形にする）
  3. コマ3の「言い分」のカード：`肢D○○○○の言い分`
  4. コマ4のチェック欄：`…（肢D○○○○は〇）`（正誤を括弧で添える）
  ※ 試験の問の記号（「肢ウ」「肢エ」）は図に使わず、肢IDにそろえる。
- 画像の中の文言に入れてはいけないもの：図番・「図1」などの通し番号／個人の演習結果（誤答の回数、「履歴」「★」「のべ」など）／「決定木」「判定木」「ツリー」（『判定の流れ図』『分かれ道』と書く）。設計メモ（design・rev）にも個人の解答履歴を書かない（check_all.py が「誤答」「履歴」を検出する）。
- 事例の当事者は、A・B・Cのラテン文字でなく、甲・乙・丙や役割（「加わる者」など）の日本語で書く。登場人物はトリ先生と藍子。HTML描画版は使わない。画像は生成しない。
- 条文の語・番号は note-articles/laws/ の原文で確かめる。記事が「条文に明記なし」「実務の取扱い」とする点は断定せず、図でも「整理」「実務の取扱い」と添える。記事と条文の文言が食い違うときは、図には条文の文言に合わせ、README の確認事項に書く。

## 3. 並びを記事の順に整える
- ファイル名の論点番号を2桁にそろえる（prompt_4koma_PA-3_… → PA-03_…、prompt_infographic_PA-1.md → PA-01.md、spec_4koma_PA-3_01.py → PA-03_01.py）。フォルダの一覧が記事の順（PA-01, 02, …）に並ぶようにする。移動は `git mv`。
- build_4koma.py の NAMES を、記事の順（論点番号順）に並べ替え、保存名の通し番号（「…_4コマN」）を記事の順の 1, 2, 3, … に振り直す（既存の再利用の論点には番号を振らない）。生成物の論点IDの表示は0埋めを外す（【PA-03】ではなく【PA-3】）。gen_infographic.py のファイル名の対応も2桁にそろえる。
- 作成済みの4コマは、番号・ファイル名・保存名以外を変えない。再生成したあと、`git diff` で、作成済みのファイルの差分が番号とパスだけであることを確かめる。
- README.md を、記事の順（論点ごと）に書き直す：成果物の一覧（図解・4コマの対応）、記事への挿入位置の案（論点ごとに「肢ごとの判定」の直後：4コマN）、型、対象外にした肢、確認事項、追記（日付つき）。

## 4. 確認

- `__pycache__` を消す。

## 5. 保存
- 変更をまとめて1コミットにし（メッセージに、新作の論点と本数、並べ替えの内容を書く）、main に push する。ブランチが main でない場合は `git push origin HEAD:main`。作業ブランチが指定されているときは、そのブランチにも push する。
```

## この指示で作業するときの注意（過去の実施から）

- 最初の実施（不動産登記法編 第1章）では、新しい4コマの設計データを書くエージェントに「肢IDの『D0000』を図の中のカードに入れない」と指示してしまい、作成済みの4コマと体裁がずれた。タグの形は、上の「肢IDのタグ」の4つにそろえること。
