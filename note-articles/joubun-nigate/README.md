# 条文別『苦手克服』シリーズ（joubun-nigate）

条文を1つ選び、①その条文が何を定めているか、②択一式の一問一答で何度も間違えてしまう理由、を整理して、noteの記事にするシリーズです（2026-10-09開始）。

年度別の過去問解説（`h17-mondai/`〜`r7-mondai/`）や、複数年度をまたぐ苦手分析（`column/nigate-NN-*.md`）とは別に、**条文を軸にして**作ります。条文の全文解説（リポジトリ直下の`law-commentary/`）とも別で、こちらは「自分が間違える理由」と、それを直すための図解・4コマが中心です。

## 置き場所

- `joubun-nigate/{法令}/art{条番号}-{項}-{内容のローマ字}/`：1つの条（または項）につき1フォルダ。法令は `fudousan-touki-hou/`（不動産登記法）から始めます。
- `common/`：各回で共通の部品。`infographic_parts.py`（図解プロンプトの共通部品）と、`check_article.py`（機械チェック）です。
- `fukushuu-chuu-no-joubun-betsu-2026-10-09.md`：復習中の肢を条文別に分類した一覧。次に作る条文を選ぶ材料です。
- 作業は`main`ブランチに直接コミットします（`CLAUDE.md`の作業ブランチの統一ルールのとおり）。

## 1回分（1フォルダ）のファイル

- `note_art{条}-{項}.md`：記事の本文（条文の原文、条文の内容の説明、間違えやすいポイント、画像挿入マーカー）
- `prompt_infographic_art{条}-{項}.md`：条文の仕組みを理解するための図解インフォグラフィックのプロンプト（必要な枚数分。記事に出てくる順に、図解1から番号を振る）
- `prompt_4koma_{番号}_{名前}.md`：4コマ解説図解のプロンプト（間違えやすいポイントごとに1本。必要な本数分）
- `prompt_midashi_art{条}-{項}.md`：note見出し画像のプロンプト（4コマ解説図解の見出し画像のプロンプトを参照して作成）
- `check_config.json`：機械チェックの設定。`python3 note-articles/joubun-nigate/common/check_article.py <フォルダ>` で実行する（標準ライブラリのみ。NG 0件が条件）
- `src/`：プロンプトの生成元（4コマの設計データ、図解のプロンプトを組み立てるスクリプト、記事の元のテンプレート）。プロンプトを直すときは、ここを直して再生成する

## 作り方の手順

1. **条文の原文を転記する**：`note-articles/laws/` から機械的に転記する（手で打ち直さない）。関連する条文（引用条文、令・規則）も `laws/` の原文で文言を確かめる。リポジトリ直下の `law-commentary/` の解説があれば、読んで整理に使う（原典は `laws/`）。
2. **関連する肢を集める**：一問一答のバンク（`tools/drill/data/items.json`）の肢のうち、その条文の判断が必要なものを集める。肢ごとの解答の履歴は、学習記録ブランチ `drill-log` の `log.jsonl`（`python3 tools/drill/drill.py`）から取れる。
3. **間違えやすい型に分ける**：肢を内容で3〜5つのグループに分け、グループごとに「どう考えて間違えるか」を整理する。誤答の多いグループが、記事の山場になる。**履歴は、グループ分けと、どこに力を入れるかを決めるためだけに使い、記事には書かない**（下の「書き方のルール」）。
4. **間違えやすいポイントを言葉にする**：グループごとに「よくある勘違い」「正しい整理」「見分け方」「たとえば」を書く。「たとえば」には、肢の記述を言い換えて載せ、正しいか誤りかを書く（年度・問題番号は書かない）。肢の正誤は、現行法令を基準にしたバンクの値に従い、肢の記事（`{年度}-mondai/`）の解説の範囲から外れない。
5. **図解の枚数を決める**：条文の仕組み（部品、対象の一覧、判定の流れ、誰が・いつから、似た制度との区別）のうち、本文だけでは分かりにくいものを1枚ずつ図にする。作り方は `note-articles/infographic-prompt-template.md`（カードポスター型・対比表型・早見表型・フローチャート型）に従う。画像の中には、図の番号を入れない。
6. **4コマの本数を決める**：誤答の型ごとに1本（重なる論点は1本にまとめてよい）。作り方は `MANGA_RULES.md` と生成器 `gen_prompts.py`・機械チェック `check_prompt.py`（ブランチ `claude/kind-bell-y3f106` の `tools/drill/manga/`）に従い、`check_prompt.py` が NG 0件・WARN 0件であることを確かめてから保存する。設計メモには【出題者のひっかけ】【受験者の勘違い・定着していない点】【対比する制度】【型の選び方】を書く。
7. **見出し画像のプロンプトを作る**：4コマ解説図解の見出し画像のプロンプト（`gen_prompts.py` の `header_prompt`）と同じ構成・同じ配色（水彩の空）で、タイトル2行（結論を書かず、問いかけにする）とサブタイトルを作る。
8. **機械チェックを通す**：`common/check_article.py` を実行して NG 0件にする。記事に個人の演習結果・問題番号が入っていないことも、ここで確かめる。
9. **記事の確認事項に、条文に明記がない整理（実務上の理解）と、画像が未生成であることを書く**。

## 書き方のルール

- 記事のタイトルは、`## 【土地家屋調査士受験生向け】条文別 苦手克服〜{法令名} {条（項）}（{条の見出し}）〜` の形にする（2026-10-09 ユーザー指示）。例：`【土地家屋調査士受験生向け】条文別 苦手克服〜不動産登記法 第40条（分筆に伴う権利の消滅の登記）〜`。
- 文体はです・ます調、全角のかっこ。Markdownの表は使わず、箇条書きにする。1段落はおよそ125字以内。
- 判例・先例の番号は書かない（内容の言及は可）。
- **記事は読者に見せるものなので、個人の演習結果（解答の回数・誤答の数・自分が何と答えたか）と、そこから分析した過程、分析の根拠にした問題番号（年度・問・肢）の列記は、記事にも画像にも載せない**（2026-10-09 ユーザー指示）。「繰り返し出題される」のような一般的な言い方にとどめ、肢は言い換えて「たとえば」で示す。図解インフォグラフィックの画像の文言にも、問題番号を載せない。**4コマの結論帯の2行目の問題番号（問題D…）は載せる**（2026-10-09 ユーザー指示）。
- 画像挿入マーカーは `> 【画像挿入】…` の引用形式で、該当する説明の直後に置く。
- 画像は、プロンプトを作るところまでが成果物。画像の生成・目視確認はユーザーが行う（生成していないことは、記事の確認事項に書く）。
