# 「すきま時間の一枚まとめ」 シリーズ設計（2026-11-16）

## 1. 読者の要望と、シリーズの狙い

> 各年度の肢別解説はありがたいが、移動中・隙間時間に確認できる「分野ごとに論点がまとまったもの」がほしい。敷地権の計算例や地積測量図の記載事項のように、絵というより字だけでもよいので、**一枚でその分野をまとめたもの**。

読み取れる条件は4つ。

| 条件 | 設計への落とし込み |
|---|---|
| 移動中・すきま時間（片手・スマホ・通信が不安定） | 1枚＝スマホ1〜2画面で読み切る。画像（PNG）単体でも成立させ、保存して通信なしで見返せるようにする |
| 分野ごと（年度ごとではない） | 年度・問題番号で切らず、「論点の型」で切る。出題年度・問題番号は載せない |
| 字だけでよい（絵より、まとまり） | 図解より**表と箇条書き**が主役。ただし「読めば手が動く」ように、計算例と記載事項は必ず入れる |
| 一枚で（網羅より、取り出しやすさ） | 1シート1テーマ。載せきれない論点は「◯◯ その2」に分ける（1枚に詰め込まない） |

**位置づけ（既存シリーズとのすみ分け）**

- 年度別の肢別解説＝「解いたあとの復習」。本シリーズ＝「解く前・移動中の**要点の再確認**」。
- 「建て付けマップ」＝条文の地図、「数字の図鑑」＝期限・金額の見取り図。本シリーズは**手続・計算・記載事項の中身**を一枚にする。数字だけの論点は図鑑に任せ、リンクで案内する。
- `topics/KD_05_*`（添付情報の早見表）のような長い個別記事（約8万字）は、本シリーズの**素材**。長編から「要点の一枚」を蒸留し、各シートの末尾から長編へ戻れるようにする。
- 個人の演習結果に基づく復習カード（`chokuzen-fukushuu-card/`、`fukushu-ronten-zukai/`）は個人用で非公開。本シリーズは公開用なので、演習結果・誤答回数・問題番号を載せない（既存ルールと同じ）。

## 2. 1シートの型（固定スロット）

すべてのシートを同じ並びにして、開けばどこに何があるかが分かるようにする。**1シート＝約600〜900字＋表1〜2個**を上限の目安にする。

| スロット | 内容 | 字数の目安 |
|---|---|---|
| ①タイトル行 | 「何についての一枚か」と、条文番号（例：不動産登記法 第40条ほか） | 1行 |
| ②結論3行 | 「この一枚で言えること」を3行。ここだけ読んでも得をする | 〜120字 |
| ③本体 | **表**（場合分け・比較・記載事項の一覧）か、**番号付きの手順**。分野の型で選ぶ（下の型表） | 表1〜2個 |
| ④計算例 or 記載例 | 数値の入った最小の具体例を1つ（計算は検算つき）。計算がない論点は「書き方の例」 | 〜150字 |
| ⑤ひっかけ | 間違えやすい点を3つまで（「〜と思いがちだが、実は〜」の1文形） | 〜150字 |
| ⑥根拠 | 条文・規則の番号だけ（原文は載せない）＋関連する長編記事へのリンク | 1〜2行 |

**文体**：である調、1文を短く、主語を省かない。条文の言い回しはそのまま使い、意訳が必要な所は意訳と分かるようにする。絵文字は使わない（スマホで文字化けしにくく、トーンも保てる）。

**シートの型（分野によって③の中身が決まる）**

| 型 | ③の中身 | 向く論点の例 |
|---|---|---|
| 場合分け表 | 「どの場合に→何が必要／できる／できない」の表 | 添付情報、合筆の制限、申請人 |
| 手順 | 番号付きの手順（5〜7ステップまで） | 地積更正を伴う分筆の流れ、座標から面積を出す手順 |
| 記載事項チェックリスト | 「書くもの／書かないもの」の2列 | 地積測量図、建物図面、各階平面図、土地所在図 |
| 計算の型 | 公式＋数値入りの例＋検算 | 敷地権の割合、床面積の求積、地積の端数処理、登録免許税 |
| 比較表 | 似たものを並べて違いを一目で | 合併／合体、分筆／分割、区分／分割 |
| 用語・定義カード | 定義を1行ずつ（空欄補充に使えるよう、語句を太字） | 筆界特定、表題部所有者、敷地権の定義 |

| C 区分建物・敷地権 | 敷地権の要件・割合・規約・移記 | 5 |
| D 申請手続の共通ルール | 申請人・代位・添付情報・登記識別情報・原本還付 | 6 |

## 4. 成果物の形（媒体別）

| 媒体 | 形 | 目的 |
|---|---|---|
| note記事 | 1シート＝1記事。スマホ表示で表が崩れないよう**表は4列まで**。冒頭に②結論3行 | 検索・シェア・購読への導線 |
| 画像（PNG、幅1080px・縦長） | 同じ内容をそのまま1枚に。**保存して通信なしで見返せる**。高さは内容に応じて変わる（実績：約2,900〜3,970px。上限4,000px） | 移動中の本命 |
| まとめPDF（分野ごと） | 分野の全シートを1ファイルに束ねる（第3弾以降） | 紙で見たい・オフライン用 |

**画像の作り方（重要な設計判断）**：このシリーズの画像は文字が主役なので、画像生成AIに描かせると誤字が出る（既存の4コマで確認済みの弱点）。そこで**HTMLで組んでPlaywrightでPNGに書き出す**。記述式の申請書画像（`note-articles-Kijyutsu/**/make_*_shinseisho_gazou.py`）と同じ方式で、誤字ゼロ・再生成容易・データ（Python/JSON）から記事と画像を同時に作れる。4コマで「HTML描画は広げない」とした決定は、キャラクターの絵と吹き出しが混ざる4コマ限定の話で、本シリーズには当てはまらない（決定の確認を依頼：§8）。

- 本文フォントは Noto Sans CJK JP。**スマホで読める大きさを下限にする**：本文34px、表30px、注記28px（1080px幅。2026-11-16、試作で3:4に収まらなかったため、固定の3:4をやめて「幅1080px・縦長」に改め、下限を36→34pxに下げた）。入らなければ内容を減らして「その2」に分ける（フォントを縮めない）。
- 配色は既存の対応に合わせる：表示＝青、権利＝薄い橙、注意（ひっかけ）＝赤橙、計算＝灰緑。ダークモードで見る人もいるので、背景は白固定の画像にして崩れを防ぐ。
- 画像にはアカウント名・URL・ハッシュタグを入れない（Instagramの既存ルール）。年度・問題番号・図番・個人の演習結果は入れない。

## 5. 作り方（既存シリーズと同じ運用）

```
note-articles/ichimai-matome/
  00-kousei.md            この設計書
  README.md               運用手順と進み具合
  src/sheets/<ID>.py      シートのデータ（スロット①〜⑥）。ここだけを手で直す
  src/build.py            データ → note記事(.md) ＋ 画像用HTML ＋ PNG
  src/check_all.py        機械チェック（NG 0件にする）
  sheets/<分野>/<ID>.md   生成された記事（手で直さない）
  sheets/<分野>/<ID>.png  生成された画像
```

**機械チェック（`check_all.py`）の項目**

1. 引用した条文・規則の番号が `note-articles/laws/` に実在する。
2. 数値入りの計算例を**コードで再計算して一致**を確かめる（敷地権の割合、床面積、端数処理）。計算例は文章に手で書かず、`build.py` が式から文字列を作る。
3. 字数・表の列数・スロットがそろっている（①〜⑥の欠け、表5列以上、1文の長すぎを検出）。
4. 禁止事項：個人の演習結果、問題番号、図番、「木／ツリー」、確かめていない主張（「頻出」「必ず出る」）。
5. 画像のオーバーフロー検査（HTMLの要素が枠を超えていないか、本文が36px未満に縮んでいないか）。

**根拠の取り扱い**：法令は `laws/` の原文で確認する。通達・先例など `laws/` にないものは、シートには載せるときに「原文は未確認」と分けて書く（`chokuzen-yosou-moshi` と同じ扱い）。法改正（住所変更登記の義務化、相続登記の義務化など）に関わるシートは、改正時点を末尾に書く。

## 7. 先に決めておくと手戻りが減ること（推奨を先頭に）

1. **記事は1シート1本か、分野ごとの長いまとめ1本か** → 推奨：1シート1本。「移動中に1枚だけ」という使い方に合う。分野ごとの束ねはPDFで提供する。
2. **公開の順番** → 推奨：要望の2枚（E-01・C-01）をまず出して反応を見る。反応が良ければ同分野を続ける。
3. **noteのマガジン** → 推奨：「すきま時間の一枚まとめ」1つのマガジンに、分野をタグで分ける（年度別マガジンとは別に作る）。
4. **タイトルの形** → 推奨：`【土地家屋調査士試験】一枚まとめ_地積測量図の記載事項` のように、先頭は【土地家屋調査士試験】で、分野名ではなく論点名で書く（検索で当たる語を先頭に）。
5. **記述式の論点の範囲** → 推奨：書き方の型（H分野）とE分野の図面だけを入れ、年度別の解説は既存の記述式記事に任せる（重複を避ける）。

## 8. 確認事項と決定（2026-11-16）

**決定済み**：①画像はHTML描画（Playwright）で作る。②第1弾12枚の内容と順番は§3のとおり。③本シリーズは**すべて無料で公開**する（§7・下の「無料と購読者向けの線引き」の案は取り下げ、長編へのリンクも無料のまま案内する）。目次は`01-mokuji.md`。

（以下は決定前の確認事項。記録として残す）

- HTML描画で画像を作る方式（§4）でよいか。AI生成の見た目の良さより、誤字ゼロと再生成の速さを優先する案。
- 第1弾の12枚の内容と順番でよいか（特に、要望の2枚以外に入れたい論点があれば）。
- 無料公開と購読者向けの線引き。第1弾は全部無料の一枚＋「長編へのリンクは購読者向け」とする案が、導線としては自然。
