## おすすめの組み合わせ

1. **主役は今のやり方（`d01.py` → ChatGPTにシート6枚を添付してプロンプトを貼る）のまま**。5本のどれも、ChatGPTでの生成やシート6枚の添付をそのまま置き換えるものではなかった。
2. そこに **5（learning-manga）の台詞の指定の書き方**（「次の日本語だけを、該当コマの吹き出しに一字一句そのまま描く」の一覧）と、**2（comic-guide）の5段構成**（画風→コマ割り→コマごと→文字の決まり→品質）を、今のプロンプトの点検項目として足すのがいちばん効く。どちらもプロンプトの書き方なので、文字を後から重ねる決まりには触れない。
3. Geminiのキーを用意してローカルで回すなら、**3（100-times）**でページごとの採用・やり直しを管理する。ただし白黒のみ・ネーム画像が要る・ライセンスが未記載の3点を承知のうえで。
4. 1（stockedge）と4（comic-generator）は使わない。

## 実際の画像を試すには（ユーザーにお願いすること）

- Gemini APIキー（課金設定つき）は、チャットに貼らず、自分のPCの `.env` に書いて、3か5を手元で動かす。このクラウドの作業場所ではキーを扱わない。
- キャラクターシート6枚を手元で添付する（3はキャラごとに複数枚を登録できる）。

## フォルダ

- `1-stockedge/`：ツールが作った制作フォルダの設定と作業指示（ここから先は画像生成が要る）
- `2-comic-guide/`：storyboard・characters・プロンプト3話分
- `3-100-times/`：模擬APIに送った依頼文（ツール固定の前置きは省略）と模擬出力の例
- `4-comic-generator/`：物語作成の指示文（台本を「取り入れる要素」として渡した形）
- `5-learning-manga/`：流し込んだ台本JSON、画面の写し、ChatGPT用のまとめプロンプト
- `neme/`：台本から作った簡易ネームと作画指示書（3の入力用。完成画像に文字を重ねるものではない）
- `scripts/`：上の試作を作ったスクリプト（ツール本体のコードは含まない）

個人の演習結果は記事・画像に出さない、noteへの投稿はユーザーが手で行う、という方針は変えていない。
