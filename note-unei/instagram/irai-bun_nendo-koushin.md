# 依頼文：Q1〜Q20記事の品質チェックとInstagram用プロンプトの更新を、別の年度・別チャットで行うとき

令和7年度（r7-mondai）で行った「①択一式Q1〜Q20の記事の品質チェック→②Instagram用の図解プロンプトの再同期→
③画像ファイルのリネームのルールの確認」の一連の作業を、別の年度で別チャット（Claude Code のセッション）に
行わせるときに貼り付ける依頼文です。

## 使い方

- 下のコードブロックの中身をそのままチャットに貼る
- 書き換えるのは冒頭の【対象年度】の1行だけ（年度・フォルダ名・年度コード・Instagram用の年度の記号の4つ）
- フォルダ名・年度コード・Instagram用の年度の記号の対応は次のとおり（`make_ig_prompts.py`の`year_code`と
  `short_code`、`note-articles/`のフォルダ名で使い分けが違う点に注意）

| 元号・年 | フォルダ名（`note-articles/`配下） | 年度コード（`R07.md`等のファイル名） | Instagram用の年度の記号（画像ファイル名） |
|---|---|---|---|
| 令和1〜8年 | `r1-mondai`〜`r8-mondai` | `R01`〜`R08`（0埋め2桁） | `R1`〜`R8`（0埋めしない） |
| 平成17〜30年 | `h17-mondai`〜`h30-mondai` | `H17`〜`H30` | `H17`〜`H30` |

- 添付資料は不要（対象年度の記事は作成済みであることが前提）。記事そのものの内容（結論・条文の判断）を
  書き換える依頼ではなく、品質チェックとInstagram用プロンプトの再同期が目的

## 保守のルール

- `note-articles/infographic-prompt-template.md`に②③④⑤の新しいルールが加わったら、この依頼文の
  「作業1」の確認項目も合わせて更新する
- `note-unei/instagram/prompts/README.md`の画像ファイルのリネームのルールが変わったら、この依頼文の
  「作業3」も合わせて更新する

---

```
【対象年度】令和7年度（フォルダ名：r7-mondai、年度コード：R07、Instagram用の年度の記号：R7）

GitHubリポジトリ ThREE100/chosashi-app の main ブランチで、上記年度の note-articles/{フォルダ名}/ 配下の
Q1〜Q20（q01-*.md〜q20-*.md）について、次の3つの作業を順に行ってください。完了したら main に直接
コミット・pushしてください（この指示は、そのための事前の明示的許可を兼ねます）。他セッションが並行して
mainを更新していることが多いので、pushの前に必ず git fetch origin main で最新化し、取り込んでから
pushしてください。

■ 作業1：品質チェック（直す必要がないものはそのままにする）

1. note-articles/infographic-prompt-template.md を最初から最後まで読み、現在の固定ルールを確認する
   （前回チェック後に更新されている可能性がある。CLAUDE.mdの該当節もあわせて読み、最近追加されたルールを
   見落とさない）。
2. 対象年度のq01〜q20の全ファイルを対象に、以下を機械的に確認し、違反があれば直す（違反がなければ変更
   しない）。
   - 決定木・判定木・ツリー・木に当てはめる・木では、などの樹形図の「木」の禁止語（grepで全文検索）。
     違反があれば「判定の流れ」「流れ図」「分かれ道」に直す。
   - ⑤作図ガイド型の見出し・Subtitleに肢の範囲（「ア〜オ」「1〜5」等）が書かれていないか（見出しは常に
     「（作図ガイド）」のみ、Subtitleも範囲表記を含めない）。
   - ②問題全体・④間違いノート・⑤作図ガイドの全プロンプトのコードブロックに、「絵の中の文字は、指定した
     語だけ」ルール（ILLUSTRATION TEXT RULE／DIAGRAM TEXT RULEの段落と、Final checkの確認文）が入って
     いるか。欠けていたら、CRITICAL TEXT REQUIREMENTの直後・BACKGROUND REQUIREMENTの直前に段落を挿入し、
     Final checkの末尾（"and confirm the entire canvas, edge to edge..."の直前）に確認文を追加する。
   - 正誤対比型・対比枠型のパネルで、(a) 同じ箱に○と×を両方指示する矛盾がないか、(b) 左右で1〜2文字しか
     違わない近似文字列（個数・金額など）がある場合に、明示的な区別指示（別の差し色、「同一ではない」の
     明記、Final checkでの個別確認）が入っているか。
   - Final checkの「漢字に注意」リストに挙げた漢字が、そのプロンプト本文に実際に登場しているか（登場しない
     漢字をリストに残さない。逆に、本文に何度も出てくる誤りやすい漢字がリストから漏れていないか）。
   - コードフェンス（```）の数が偶数であること、フェンス外にMarkdown表の行が紛れ込んでいないこと。
   - サブタイトルが「{年度} 午後の部 第N問」の形式を厳守しているか（他の文言を混ぜない）。
3. 修正は該当箇所の挿入・言い換えに限り、記事の結論・条文の判断は変えない。
4. 作業後、対象年度の全ファイルでコードフェンス数が偶数であることを再確認する。

■ 作業2：Instagram用の図解プロンプトの再同期

1. 作業1の修正を終えたら、リポジトリのルートで python3 note-unei/instagram/make_ig_prompts.py を実行
   する（記事は編集しない。このスクリプトは22年度分すべてを読み直して書き出すので、対象年度以外の
   ファイルも、他セッションの編集によって同時に変わることがある）。
2. git diff --stat note-unei/instagram/prompts/ で変更されたファイルを確認し、対象年度（{年度コード}.md）
   の差分が、作業1の修正を正しく反映しているか（ILLUSTRATION/DIAGRAM TEXT RULEの段落・Final checkの
   追加文など）を目で確認する。対象年度以外の変更も、同じ理由（他セッションの記事編集への追従）で生じた
   正当な差分であればそのままコミットしてよい。
3. note-unei/instagram/prompts/index.csv の対象年度の行に「要手作業」の注記が出ていないかを確認する。
   出ていたら、原因（カード数が4〜6枚でない、グループが3つ以上など）を調べて対応する。
4. note-unei/instagram/prompts/*.md 全体でコードフェンス数が偶数であることを確認する。

■ 作業3：画像ファイルのリネームのルール（確認のみ、通常は新規作業不要）

画像ファイルのリネームのルールは、note-unei/instagram/prompts/README.md の「画像ファイルのリネームの
ルール」と note-unei/instagram/README.md、CLAUDE.md のInstagramの運用の節に、年度に関わらず共通の
ルールとしてすでに記録済みです。この依頼では新しいルールを追加する必要はありません。作業2で新しく
生成された対象年度のプロンプトファイルに、問ごとの「画像のファイル名」の行
（Instagram_{Instagram用の年度の記号}_{問題番号2桁}_{記事のタイトル}）が入っていることだけ確認してください。

■ Gitの運用

- 作業前に git fetch origin main && git log HEAD..origin/main --oneline で他セッションの差分を確認し、
  必要なら git merge --ff-only、それが無理なら git pull --rebase origin main で取り込む。
- コミット・pushは「fetch → merge/rebase → push」を基本とし、競合で失敗したら数秒おいて再試行する
  （他セッションが同時にpushしていることが多い）。
- 作業1・作業2はまとめて1コミットにしてよいが、無関係な修正（他年度の再同期結果など）が混ざった場合は、
  git diffを確認してから意図した範囲だけをステージする。

■ 最後に報告すること

- 品質チェックで見つかった違反の件数と内容（問ごと・種類ごと）
- 直さなかった（すでに準拠していた）項目
- Instagram用プロンプトの再同期で、対象年度以外に変更が及んだファイルがあれば、その一覧
- コミットハッシュとpush結果
